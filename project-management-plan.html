Project Plan for a University Software Asset Management Database

This assignment applies the six-phase project management model presented by Baars (2006) to the planning of a university software asset management database.

Last Updated: June 7, 2026

Project Plan for a University Software Asset Management Database

Antonio Fernandez

Introduction

Effective project management is crucial for ensuring that projects are completed successfully. According to Baars (2006), dividing a project into different phases will allow a project manager to have greater control over the project. The six-phase project management model by Baars (2006) will be used to create a database that will allow a university to track its installed software. This database will allow the institution to track information regarding the software licenses, the different departments that use the software, the software versions, and other information that is important for the management of the software that is installed on its computers. As the project manager for this project, I will be the individual that is in overall charge of the project, making sure that the project is completed as efficiently and effectively as possible.

Initiation Phase

The initiation phase will focus upon determining whether the project is feasible and worthwhile. During this initial phase, I would meet with the administrators of the university, as well as the IT department to determine if there is a need for such a database. Many universities keep track of their software assets in a variety of different ways, leading to licensing and management issues. The purpose of this project would be to create a database for the university to track its installed software and manage its licenses accordingly.

A project proposal would be created during this stage, which would include a description of the project, the goals that it will accomplish, the budget for the project, the schedule for the project, the individuals that will be stakeholders in the project, and any potential risks for the project. Once this proposal is created and approved by the stakeholders, the project will enter the next stage of project management (Baars, 2006).

Definition Phase

The definition phase will focus upon determining the requirements of the database. During this stage, I will meet with various stakeholders of the project to determine the information that will be included in the software asset management database. For instance, I can determine the requirements of the database to include information regarding the software names, the vendors of that software, the license for that software, the date that it was installed into the computers in the university, the dates on which that software is licensed to be installed, the departments within the university that use those software packages, and the computers on which that software is installed.

During this phase, I will also define which information will not be included in the database, to avoid potential scope creep for the project. During this phase I will also define the roles of the team members, and the schedule for completing the project. These components of the project will help to ensure that each team member understands their role in the project, as well as the time in which they will be completing their specific portion of the project (Baars, 2006).

Design Phase

The design phase will focus upon creating detailed plans for the project. While the assignment does not ask for the development of the database for this project, various plans will need to be made regarding the role of each project manager and team member in the project, the plans for testing the database once it is created, and the training of the team members for which the software will be used.

During this stage, the project manager will create a detailed plan for each portion of the project, as well as developing a project timeline. During this stage, the project manager will also create a list of the potential risks of the project, and create a plan for each of those risks to ensure that the project is completed successfully (Baars, 2006).

Development Phase

During the development phase, the actual development of the database will occur. For instance, the database developers will be creating the database according to the plans that were made during the design phase. During this phase, meetings will be held between the team members to review the development of the database, and to address any issues that emerge during the development of the database.

Each team member will be required to submit a report that describes the status of their portion of the database, as well as identifying any risks or potential issues with their portion of the development. Quality assurance testing will be performed during this phase to ensure that the database is functioning according to the specifications that were created during the design phase of the project.

Implementation Phase

During the implementation phase, the database will be implemented into the university. During this phase, any existing information regarding the software that is currently installed in the university will be loaded into the database. During this phase, a test implementation can be performed within a specific department within the university prior to implementing the database into the remainder of the school.

During this phase, training will be provided to any personnel within the school who will use the software. The data will be tested during the implementation phase to ensure that it is accurate and the software is functioning properly.

Follow-up Phase

The follow-up phase will occur after the implementation of the database. During this phase, I will meet with the stakeholders and any other individuals that use the database to evaluate the success of the database. Feedback will be collected from these individuals to determine if the goals that were established for the database have been accomplished.

During this phase, I will review the successes and challenges of the project to determine what could have been done differently in the future should similar projects be undertaken. During this stage, the final reports will be created for the project, the documentation will be archived, and responsibility for the database will be given to the IT department within the university. At this point, the project will be considered complete.

Conclusion

A six-phase project management model can be used to effectively manage the creation of a software asset management database for a university. Each phase of the project management model has specific goals that should be accomplished during each stage of the project. By planning and executing each of these phases, the goals of the project can be accomplished. The project management model ensures that each component of the project is considered and managed for success (Baars, 2006).
